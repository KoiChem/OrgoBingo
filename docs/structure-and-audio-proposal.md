# 構造式の作図改善と効果音安定化：実装方針案

検討日：2026-10-29。調査時点の方針案。ユーザーから本方針に沿った実装・公開と、元素ビンゴを含む効果音修正の承認を受け、実施する。

## 目的と対象

- OrgoBingoの初期31構造式を、ユーザー提示の3画像に見られる教科書型の半構造式へ揃える。
- 元素ビンゴの効果音を、特に報告されたiPadOS 17・Chromeで初回から安定して開始・復帰できるようにする。
- 作図基準・生成元・比較画像・確認結果をリポジトリに残し、今後の化合物追加で再利用する。
- 添付の複雑な化合物は描き方の参考であり、新規マスター登録の指示ではない。

## 現状の確認結果

### 構造式

現行SVGは、多くが太字の横一列の文字列であり、アセトンは `CH3–C(=O)–CH3`、2-ブタノールは `CH3–CH(OH)–CH2–CH3` の形。添付例のような、上下に展開したカルボニル基やヒドロキシ基、文字間と独立した価標の表現にはなっていない。

前回の「分子式が正しい」「SVGが読める」という確認だけでは、今回求められた文字・価標の位置バランスを満たしたとは扱わない。

### 効果音

公開版の元素ビンゴの音声処理が、手元で確認した処理と一致することを確認した。音声処理自体は直前のFisher–Yates変更対象ではない。

現行音声コードを抽出し、状態を制御したAudioContextの模擬検証で次を確認した。

1. windowの初回click/keydownでだけ解除処理が動く。要素側のモード切替処理は、そのwindowの解除処理より先に呼ばれ得るため、最初の切替音は解除前に捨てられる。
2. `resume()` の完了前に `audioAllowed=true` となり、状態がsuspendedのまま発音要求を出す。
3. 一度解除した後にinterruptedへ移行しても、`playTone()` から再開要求は出ない。模擬検証でもresume呼び出し回数が増えなかった。
4. resume失敗の処理、closed状態からの回復、非表示・復帰後の発音整理、終了ノードの切断がない。

これらは報告された「初めから鳴らず、途中から鳴ることもある」と整合する欠陥。ただし、報告された実機でどの条件が直接原因だったかはまだ確定していない。模擬検証は実スピーカーでの可聴性を証明しない。

## 構造式：推奨する実装

### 作図規則

文字列を一括表示する方法から、原子・原子団のラベルと価標を別々に配置する方法へ変更する。

- 元素記号は添付例に近い通常ウェイトの読みやすいサンセリフ体を基本とする。
- 数字は主文字と同じベースラインに置かず、適切に小さい下付きにする。
- C=Oは原則としてCの上下にOを置き、2本の独立した線で表す。C(=O)の括弧書きは使わない。
- アルコール性OH、分岐CH3は、該当する炭素から上下へ結合させる。CH(OH)や(CH3)3Cだけで済ませない。
- 価標はダッシュの文字ではなくSVGの線とする。主鎖の水平線、上下の垂直線、不飽和結合周辺の斜線を揃える。
- 結合先はラベル全体の中心ではなく、実際に結合する原子の位置を基準にする。CH3やHOなどの向きと結合先にも注意する。
- 文字・添字と価標の間に適切な空きを作り、接触・食い込み・不自然な離れをなくす。
- マレイン酸とフマル酸はcis/transの配置を維持する。今回必要のない立体くさびや不斉炭素の記号は加えない。
- 長鎖脂肪酸では(CH2)nの省略を利用できるが、末端のカルボキシ基は展開する。

### 寸法の揃え方

基準文字高をHとして、結合長、線幅、二重線の間隔、文字と線の空き、添字サイズ・下げ量を比率で管理する。最初の代表図で添付例と比較して値を決め、その後31種を同じ値で描く。

添字は主文字の約0.6〜0.7倍を調整開始点とする。これは合格値の決め打ちではない。実際の字形・縮小表示で確認し、採用値を記録する。全ラベルに同じ中央揃えを機械的に適用せず、結合原子のアンカーと文字の実際の輪郭を使う。

### 生成・フォントの方式

推奨は、編集可能なラベル・座標定義から静的SVGを生成し、配信するSVGの文字は固定したフォントの輪郭へ変換する方法。実装時にフォントの再配布・変換条件を確認し、生成に使った版・ライセンスを残す。

これにより、閲覧端末のArial等へのフォント置換で文字幅や価標との間隔が変わることを避ける。意味のあるラベルと座標は生成元へ残し、パスの手編集は行わない。画像の代替テキストも維持する。

SVG内のtextを残す方式は変更が容易だが、端末間の字体・位置差が残る。化学描画ライブラリによる全自動レイアウトは今回の31種と見本への忠実さに対して導入・調整負担が大きいため、採用しない。

生成器で共通化するのは、ラベル、添字、単結合・二重結合、今回繰り返し登場する配置だけとする。汎用の分子描画エンジンや構造式エディタは作らない。

### 検証・完了条件

1. アセトン、酢酸、酢酸エチル、2-ブタノール、グリセリン、2-メチル-2-プロパノール、cis/transの組を代表図とする。
2. 添付例の該当モチーフと代表図を、文字高を揃えて並べる。異なる化合物を同一画像としてピクセル比較しない。
3. 文字の太さ、添字の位置、C=Oの中心、結合原子のアンカー、線端の空き、結合長・角度を確認し、基準を確定する。
4. 全31種を生成し、XML、必要なviewBox、輪郭の欠け、ラベルと価標の重なり、分子式・結合・異性体を確認する。
5. 全31種の一覧比較に加え、実アプリのメイン表示・履歴・設定プレビューで確認する。代表図だけの合格で31種全体を完了にしない。
6. ブラウザで確認可能なChromium/WebKitと、利用可能な実iPadで表示を確認する。実プロジェクターは別の確認項目とする。
7. 見本との比較で差が残る項目を記録して修正し、同じ比較で改善を確認する。新たな変更・差分・懸念がなければ通過済み検証を繰り返さない。

### 次の化合物追加へ残すもの

- `docs/structure-style-guide.md`：文字・添字・価標・アンカー・官能基・縮合表記の基準、採用寸法と理由、正しい例と避ける例。
- `docs/structure-review/`：参照画像、代表図の比較、31種一覧、変更前後、残った課題と確認環境。添付画像のノイズやスキャンの傾きを模倣しない。
- SVGの生成元と再生成コマンド：追加時は生成元を編集して同じ手順を使用する。
- 追加チェックリスト：化学的な正確さ、作図規則、メイン・履歴・プレビュー、必要な端末確認。

これらはアプリ内の管理機能や、Codexの個人メモリーではなく、対象リポジトリ内の開発資料として記録する。

## 効果音：推奨する実装

### 再現と原因の切り分け

報告条件はiPadOS 17・Chrome。実装前に、初回のスタート・モード切替、再読み込み後、連続抽選、別タブ・別アプリ・画面ロックからの復帰を分けて確認する。ChromeとiPadOSの正確な版は取得可能な範囲で記録する。

調査用の記録項目は、操作時刻、ユーザー操作中か、AudioContext状態、resume開始・完了・失敗、currentTimeの進行、発音予定時刻。音が聞こえたかは実機で別に確認する。常設の詳細ログUIは追加しない。

### 修正内容

- 初回だけのwindow解除依存をやめ、スタート・次へ・モード切替・対応キーのユーザー操作内で音声準備を先に行う。ユーザー操作の外や、通信await後に初めてresumeしない。
- 1つのAudioContextを基本に再利用する。解除要求を重複させず、runningになるまで成功扱いしない。
- suspended/interruptedは操作のたびに必要ならresumeし、closedは次の操作で再作成する。resume拒否・未完了を扱い、無限リトライしない。
- 実機でresumeだけでは復帰しない条件が残る場合に限り、進行停止を診断して、次のユーザー操作内で1回だけContext再作成を試す。鳴らないたびにContextを増やす方式にはしない。
- 再開待ちの古い短音は溜め込まない。準備できた時点の演出だけを鳴らし、突然まとめて鳴ることを防ぐ。
- 確定時の2音はAudioContextの時刻を使って間隔を指定する。古いsetTimeout音がリセットや別ラウンド後に鳴らないよう、予約・実行済みノードを管理する。
- ページが隠れたら古い発音予約を捨てる。復帰時に状態を確認し、必要な再開は次のユーザー操作で行う。裏で無音を流し続ける方式は使わない。
- 音の立ち上がりと減衰を短く滑らかにし、終了したノードを切断する。音量を上げるだけの対応はしない。
- 回復できなくても抽選や履歴を止めない。必要時だけ「音声を再開」操作を出し、ユーザー操作から再試行できるようにする。

元素ビンゴを主対象にする。有機ビンゴにもresume完了未確認・中断復帰未対応の類似処理があるため、そこで同じ原因による問題を残さないよう、必要な音声処理を揃える。両リポジトリは静的アプリとして独立させ、共通の外部配信サービスには依存させない。

### 検証・完了条件

- 状態を制御したテスト：resumeの遅延・拒否、interrupted、closed、連打、非表示復帰、リセット後の遅延音、発音ノードの後始末。
- ブラウザ操作：初回スタート、初回モード切替、マウス・タッチ・キーボード、抽選・履歴・セット選択の回帰確認。
- 実iPadOS 17・Chrome：初回からの可聴確認と復帰後の確認。実機を利用できない場合は、この確認を未実施として残し、完全解消とは報告しない。
- OSの消音、音量ゼロ、ブラウザ設定、Bluetooth/外部出力先までアプリで上書きすることは保証しない。通常の音声出力が利用可能な状態で、初回から鳴り、アプリ側の中断から回復できることを目標にする。

## 進める順序

代表構造式と比較基準の確定 → 全31種の修正・記録 → 音声の再現ケース固定と修正 → ローカル確認 → 別途公開を行う場合は公開資産と公開ページを確認する。
