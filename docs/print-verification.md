# A4印刷の仕様と検証（2026-10-30）

- `OrgoPrint.open(compounds, {title, mode, enabledIds})` は渡された登録順データをコピーし、別ウインドウで読み取り専用プレビューを開く。未保存の日本語名もコピー時点の内容を使う。
- マスターは常に全件。セットは既存の抽選ONのみを初期値とし、セット内すべてに切替可能。元画面の抽選ON/OFF、検索、分類、並べ替えを変更しない。
- A4縦、余白10mm、内容190×276mm。30件は15行×2列、20件は10行×2列。各ページの左列上から下、右列上から下。残りページも同じ行高。日本語名と既存SVGだけを印刷し、操作・題名・番号・分類は印刷しない。
- 全SVG・CSS・フォントの読込を待って印刷ボタンを有効にする。SVG/CSS読込失敗、空対象、枠に収まらない名前は明示し、印刷を無効にする。既存SVGを描き替えない。

## 実施済み

`node --test tests/print.test.cjs`：0/1/20/21/30/31/32件について20件・30件両方のページ分割、登録順保持、マスター全件、セット対象の選択を確認（15テスト）。

実データ32件を独立したPlaywright + Google Chrome 156でPDF出力。Playwright MCPは設定UI検証とブラウザを共有しており、PDF生成はローカルPlaywrightを使用。30件は30+2、20件は20+12で各2ページ。`pdfinfo`で594.96×841.92ptのA4を確認。PopplerでPNG化し、両設定の1ページ目と残りページを目視確認。長い名前の折返し、縦長のフマル酸、行高維持、余白、ページ外への切断がないことを確認。

検証用PDFは `/private/tmp/orgo-30.pdf` と `/private/tmp/orgo-20.pdf`。1000px高PNGの非白色画素の境界は20件1ページ目 `(34,34)-(673,962)`、30件2ページ目 `(34,34)-(353,157)`。上下余白を含むPDF全体で、画像表示側の余白省略による見かけ上の切断と区別して確認した。

独立したChromeブラウザで追加確認：SVG要求の失敗、CSS要求の失敗、セットの抽選ONが0件の場合はいずれもエラーを表示し印刷ボタンが無効。プレビュー起動後に元データの名前を書換えてもスナップショットが保持されることを確認。読込が完了しない場合は15秒でエラーにする。

## 実寸と限界

30件の行高18.4mm、SVG領域の高さ16mm。20件の行高27.6mm、SVG領域の高さ25.2mm。フマル酸の既存viewBox高さ397.984に対し、Hの字形高さ33.0234なので、印刷時のHの実寸は30件で約1.33mm、20件で約2.09mm。20件表示で拡大できるが、構造式ごとの縦横比を保つため字形サイズは全構造で均一ではない。実プリンター・紙上の読取りやiPadのシステム印刷は未検証。

ブラウザの印刷設定はA4縦・倍率100%、ヘッダーとフッターOFFを指定する。PDF保存はブラウザの印刷画面の保存先から行う。

CSS失敗・SVG失敗・ONが0件・編集中データのスナップショット保持の4ケースも独立ブラウザで確認した。PDFの記録は `print-review/` に保存。
